# StudyBot

StudyBotは、Discordのボイスチャンネル滞在時間と資格学習の結果を記録する個人用Botです。

現在は次の資格取得ロードマップを想定しています。

1. 情報セキュリティマネジメント（SG）
2. 基本情報技術者試験（FE）
3. 医療情報技師

SGでは、過去問道場の問題数・正答率・分野を記録し、累計成績、要復習候補、学習計画を確認できます。

## 主な機能

- ボイスチャンネル「勉強部屋」の滞在時間を自動記録し、退出時にボタンから結果を記録
- 平日の夜と土日祝の朝に、今日の復習・週目標・試験までの日数をまとめて通知
- 毎週日曜の夜に週間レポートを自動で投稿
- 勉強時間と正答率の推移をグラフ画像で表示
- テキストチャンネル「勉強ログ」の投稿を学習ログとして保存
- `/sg log` からSG過去問道場の問題数・正答率・分野を正確に登録
- `/sg glossary` でSG用語を分野別の一覧・検索・単語帳で確認
- `/review add` で誤答を登録し、`/review start` で1問ずつ解き直し
- `/sg progress` で14分野と科目Bの進捗を表示
- `/sg b` で科目Bの演習結果と判断ミスを記録
- `/plan new` と `/plan status` で週目標と実績を管理
- `/plan exam` で試験日を年・月・日から選んで設定し、残り日数と連続学習日数を表示
- `/data` で保存データの確認・修正・リセット
- Ollamaによる学習ログ分析と次回メニューの提案
- SQLiteによるローカル保存

## 動作環境

- Windows 10またはWindows 11
- Python 3.11以降
- Discord Botとそのトークン
- Ollama（AI分析機能を使う場合）
- Ollamaモデル `qwen3:8b`（AI分析機能を使う場合）

Gitは更新時に便利ですが、ZIPで保存した場合は必須ではありません。

コマンドは用途ごとにまとめています。`/help` でいつでも一覧を確認できます。

| `/review` | `add` `list` `start` `answer` | 誤答の登録・復習予定・1問ずつ解き直し・結果だけ登録 |

## 1. Discord Botを準備する

1. [Discord Developer Portal](https://discord.com/developers/applications) でApplicationを作成します。
2. `Bot` 画面からBotを追加し、トークンを取得します。
3. `Privileged Gateway Intents` の `Message Content Intent` を有効にします。
4. `OAuth2` のURL Generatorで `bot` と `applications.commands` を選択します。
5. Botに `View Channels`、`Send Messages`、`Read Message History` の権限を付けてサーバーへ招待します。

トークンはパスワードと同じ扱いです。他人へ渡したり、GitHubへ登録したりしないでください。

## 2. Discordサーバーにチャンネルを作る

次の名前でチャンネルを作成します。

- ボイスチャンネル：`勉強部屋`
- テキストチャンネル：`勉強ログ`
- テキストチャンネル：`SG用語集`（SG用語集を使う場合）

Botは最初この名前でチャンネルを探します。名前を変えたい場合や別のチャンネルを使いたい場合は、Botの起動後に `/setup` でチャンネルを選んでください（選んだチャンネルはIDで覚えるので、あとで名前を変えても動きます）。

## 3. StudyBotを保存する

Gitを使用する場合：

```powershell
git clone https://github.com/8dbdb8/Study-bot.git
cd Study-bot
```

Gitを使用しない場合は、GitHubの `Code` からZIPを保存して展開します。

## 4. 初回セットアップを実行する

展開したフォルダ内の `setup_studybot.bat` をダブルクリックします。

このスクリプトは次の処理を行います。

- `.venv` にPython仮想環境を作成
- `requirements.txt` から必要なライブラリを導入
- `data` フォルダを作成
- `.env.example` から `.env` を作成
- Ollamaが導入済みなら `qwen3:8b` を準備

既存の `.env` は上書きしません。

## 5. Discordトークンを設定する

セットアップ後に `.env` をテキストエディタで開き、次の値を実際のBotトークンへ置き換えます。

```dotenv
DISCORD_TOKEN=replace_with_your_discord_bot_token
```

引用符は不要です。`.env` は `.gitignore` に登録されているため、GitHubには送信されません。

## 6. Ollamaを準備する

AI分析機能を使う場合は、[Ollama for Windows](https://ollama.com/download/windows) を導入します。

セットアップ時にモデルを取得できなかった場合は、PowerShellで次を実行します。

```powershell
ollama pull qwen3:8b
```

Ollamaがなくても `/sg log`、学習時間、DB保存などの基本機能は利用できます。AIを使用するコマンドだけ利用できなくなります。

## 7. Botを起動する

`start_studybot.bat` をダブルクリックします。

起動スクリプトは自身が置かれているフォルダを自動的に使用するため、任意の保存場所で動作します。ログは `studybot.log` に保存されます。

起動後、Discordで `/help` を実行して、コマンド一覧が表示されることを確認してください。

## SG過去問道場の記録

Discordで `/sg log` を実行します。

1. 学習した分野を1つ選択します。
2. `問題数と正答率を入力` を押します。
3. 問題数、正答率、任意のメモを入力します。

正答率は小数第2位を四捨五入し、小数第1位で保存されます。複数分野を解いた場合は分野ごとに登録してください。

## 試験日と連続学習日数

`/plan exam` を実行すると、現在の最優先資格の試験日を設定する画面が本人だけに表示されます。

1. 年（今年〜2年後）を選択します。
2. 月を選択します。今年は今月以降だけが表示されます。
3. 日を選択します。曜日つきで表示され、その月に存在しない日や過去の日は出ません。31日ある月は「1〜16日」「17〜31日」の2つに分かれます。
4. `この日で保存` を押します。

設定した試験日は `/plan roadmap`、`/plan status`、勉強部屋の退出通知に「あと何日（約何週間）」として表示されます。`/plan new` で `weeks` を省略すると、試験日までの週数（最大16週）で計画を作成します。同じ画面から試験日の削除もできます。

連続学習日数は、勉強部屋の滞在記録か `勉強ログ` への投稿がある日を数えます。今日まだ記録がなくても、昨日まで続いていれば途切れません。`/time today` と退出通知に表示されます。

## 勉強部屋を出たときの通知

`勉強部屋` から退出すると、`勉強ログ` に今回・今日・今週の勉強時間、曜日ごとの推移、連続学習日数、試験までの日数をまとめて投稿します。

通知の下にある `SG過去問を記録`・`科目Bを記録`・`誤答を登録` を押すと、`/sg log`・`/sg b`・`/review add` と同じ入力画面が押した本人にだけ表示されます。ボタンはBotを再起動したあとも使えます。

## 学習メニュー（平日は夜・土日祝は朝）

平日は19:00、土日と祝日（振替休日を含む）は7:00に、`勉強ログ` へ本人あての学習メニューを投稿します。祝日は `jpholiday` で判定します。

- 試験までの日数と連続学習日数
- 今日が復習日の誤答（最大5件と残りの件数）
- 週次計画の今週の進み具合と、1日あたりに必要な問題数
- 10問以上解いて直近の正答率が60%未満の分野

今日の復習・有効な週次計画・これからの試験日のどれもない人には送りません。送信先は、その人が最近勉強したサーバーです。同じ日に二度は送りません。送る時刻にBotが止まっていた場合も、その日の22:00までに起動すればその日の分を送ります。

`復習を始める` を押すと、今日の復習を1問ずつ表示します。`正解した`・`また間違えた`・`あとで` で進み、結果は `/review answer` と同じように記録されます。`/review start` でも同じ画面を開けます。

通知は `/plan notify menu:オフ` で止め、`オン` で再開できます。送る時刻は `.env` に `STUDYBOT_DIGEST_TIME_WEEKDAY=20:00`（平日）や `STUDYBOT_DIGEST_TIME_HOLIDAY=08:00`（土日祝）のように書くと変えられます。

## 週間レポート

毎週日曜の21:00に、その週（月曜〜日曜）に勉強の記録がある人へ、`/ai report` と同じ週間レポートを `勉強ログ` に投稿します。勉強時間・問題数・平均正答率と、AIによる振り返り（今週の実績・課題・来週の方針）が入ります。Ollamaに接続できないときは数字のまとめだけを送ります。同じ週に二度は送りません。21:00にBotが止まっていた場合は、日曜のうちに起動すれば送ります。

週間レポートは `/plan notify report:オフ` で止め、`オン` で再開できます。`/plan notify` だけを実行すると、今の設定と送る時刻を確認できます。

## グラフ

- `/time chart`：日ごとの勉強時間の棒グラフと、7日平均の線を表示します。`days` で2週間・4週間・12週間を選べます（省略時は4週間）。
- `/sg chart`：SGの正答率の推移（上）と、日ごとの問題数（下）を表示します。`category` で14分野から1つを選ぶと、その分野だけのグラフになります（省略時は全体）。点線は合格目安の60%です。

グラフはDiscordのダークテーマに合わせた画像で送ります。日本語はWindowsの「Yu Gothic」などのフォントで表示します。

## SG用語集

テキストチャンネル `SG用語集` で `/sg glossary` を実行すると、用語と意味の一覧が表示されます。`category` で11分野または「全分野」を候補から選べます。未選択時は全分野です。`query` には用語・意味・分野・小分類の一部を入力でき、分野を選んだ場合はその分野内で検索します。`mode:単語帳` を選ぶと、絞り込んだ用語を1件ずつ表示します。画面内のボタンで一覧と単語帳を切り替えられます。

一覧では「前へ」「次へ」でページを移動します。単語帳では「意味を見る」で裏面を開き、「前へ」「次へ」「シャッフル」で片手の操作だけで用語を進められます。意味が長い場合は「次へ」で続きを表示します。スラッシュコマンドで開いた画面は実行者だけに表示され、ボタンは5分間使えます。

単語帳で意味を開くと、自己評価として「できた」「できなかった」「要復習」「微妙」の4つから1つ選べます。選択すると本人の評価をDBに保存して次のカードへ進みます。最後のカードではその場にとどまり、評価を選び直せます。一覧では評価ボタンは表示されません。保存済みの評価は、次回そのカードの意味を開いたときにも確認できます。単語帳画面の「自己評価で絞る」では4つの評価から1つ以上を選び、本人の保存済み評価が一致する単語だけを表示できます。未評価の単語は絞り込み時に含まれません。選択した単語はその回の単語帳に固定され、途中で評価を変えても消えません。評価を選び直すと、最新の評価で絞り込み直します。「絞り込み解除」で全単語に戻せます。`/data` では評価した用語の件数を確認でき、自己評価だけをリセットすることもできます。

最初の自己評価を選ぶと、`SG用語集` チャンネルに今回の学習記録を投稿します。その後の評価では同じ投稿を更新し、取り組んだ問題数と4択それぞれの件数を残します。問題数はその回に評価した異なる用語の数です。同じ用語の評価を選び直した場合は、問題数を増やさず内訳だけを更新します。カードごとの評価操作も専用の `data/sg_glossary_history.db` に履歴として保存します。単語帳画面を途中で閉じても、それまでの記録は残ります。`/data` のリセットはこの専用DBの履歴には影響しません。

データは `data/sg_glossary.json` から読みます。ファイルがない場合、コマンドは配置先と参照先を案内します。ファイルはUTF-8で、配列、または `entries` 配列を含むオブジェクトにしてください。各項目には `term` が必要です。`meaning`、`category`、`subcategory`、`source_url` は空欄でも読み込めます。意味が空欄の用語は「意味未登録」と表示し、単語帳では参考サイトへのリンクを示します。

分野の選択肢は付属データの11分野です。別の分野名を持つデータに差し替えた場合は、「全分野」を選んで `query` で絞り込めます。

付属データは[IPA公式シラバス Ver.4.1](https://www.ipa.go.jp/shiken/syllabus/nl10bi0000007tch-att/syllabus_sg_ver4_1.pdf)の用語例から抽出した829件（810語）です。参照サイトの911件とは用語の区切り方が異なります。意味の説明文は独自に作成しています。説明文は学習用の簡潔な補助であり、誤りを含む可能性があります。カードの「用語出典」は用語の出所を示し、意味の説明文の出典ではありません。sg-siken.comの用語解説文を複製したものではありません。

[参照サイトの利用条件](https://www.sg-siken.com/thissiteis.html)を確認し、説明文を使う許諾がある場合は、その範囲で `data/sg_glossary.json` を差し替えられます。データ内では同じ用語を異なる分野に複数掲載できます。

```json
{
  "entries": [
    {
      "term": "サンプル用語",
      "meaning": "自分で記入した意味",
      "category": "サンプル分野",
      "source_url": "https://example.com/"
    }
  ]
}
```

## 誤答の復習

`/review add` で14分野から1つ選び、問題のURLまたは番号、間違えた理由、任意のメモを登録します。問題文そのものを入力する必要はありません。

`/review list` で今日までに復習する問題を確認できます。今後の予定も含める場合は `/review list all_items:true` を使用します。各問題には `#1` のようなIDが表示されます。

再挑戦後に `/review answer mistake_id:1 result:正解` または `result:不正解` を選びます。最初の復習日は登録の翌日です。正解すると次回は3日後、さらに正解すると7日後になり、3回連続正解で完了します。不正解なら連続正解数は0に戻り、翌日に再挑戦します。

## 14分野と科目B

`/sg progress` には14分野それぞれの累計問題数、直近の正答率、最終学習日を表示します。問題数が10問未満なら「記録少」、一度も解いていなければ「未着手」です。過去の大分類だけのログは、14分野へ推測で割り振らず「分野未特定」に表示します。

科目Bを解いたら `/sg b` を使用します。テーマを選び、問題数と正解数を入力してください。誤答がある場合は判断を間違えた理由も入力します。科目Bの結果は14分野の進捗とは別に `/sg progress` に表示されます。

## 週次計画の達成確認

`/plan new weeks:6 weekly_questions:30` で6週間、毎週30問を基本目標とする計画を保存できます。`weekly_questions` の省略時は30問です。以前の計画は履歴として残り、新しい計画が有効になります。

`/plan status` で週ごとの目標と実際の問題数を確認します。第1週は計画を作った日から7日間です。未達分は翌週へ繰り越しますが、上乗せは基本目標の50%が上限です。例えば30問目標で18問解いた場合、翌週の目標は42問になります。科目Aと科目Bの記録を合算します。

Ollamaに接続できない場合も数値目標は保存され、`/plan status` は使用できます。文章による学習計画だけ未生成になります。

## 保存データの確認・修正・リセット

Discordで `/data` を実行すると、自分のSGログ・通話勉強時間・誤答・週次計画の件数と最近の記録が本人だけに表示されます。

- **修正**：データの種類、記録、修正項目を順に選びます。分野は選択式、数値やメモは入力欄を使います。変更前後を確認してから「修正を確定」を押してください。SGの累計成績と週次実績は元ログの修正後に再計算されます。
- **リセット**：SGログ、完了済み通話時間、誤答リスト、週次計画、または自分の全学習データから範囲を選びます。削除件数の最終確認後に「リセットを確定」を押してください。通話勉強中は時間を含むリセットができません。
- **そのまま**：変更せず終了します。

旧形式で分野が未特定または複数候補のSGログは、先に14分野から正しい分野を選んでから問題数・正答率を修正します。科目Bは正解数から正答率を再計算します。編集・リセットの対象は実行者本人のDB記録のみで、元のDiscord投稿は変更・削除されません。過去の投稿に書かれた累計値が古くなる場合は、`/data` や `/sg status` の現在値を確認してください。リセットは取り消せないため、必要なら先に `data/study.db` をバックアップしてください。

## ファイル構成

`bot.py` は起動用の入口で、Botの中身は `studybot/` フォルダに機能ごとに分かれています。

| 場所 | 内容 |
| --- | --- |
| `bot.py` | 起動スクリプト（`start_studybot.bat` から呼ばれる） |
| `studybot/app.py` | Botの組み立て・起動時の処理 |
| `studybot/config.py` | 設定値（チャンネルの既定名、AIモデル、通知時刻など） |
| `studybot/channels.py` | `/setup` のチャンネル設定と、チャンネルの探し方 |
| `studybot/groups.py` | `/sg` などのコマンドグループと `/help` |
| `studybot/features/` | コマンドごとの処理（`sg.py`・`review.py`・`time.py`・`plan.py`・`exam.py`・`ai.py`・`data.py`・`glossary.py`・`digest.py`・`setup.py`） |
| `studybot/voice.py` | 勉強部屋の入退室と退出時の通知 |
| `studybot/study_log_events.py` | #勉強ログ への投稿の保存とAI解析 |
| `studybot/forms.py` | SG過去問・科目B・誤答の入力画面 |
| `studybot/embeds.py` | 枠付き表示（Embed）の組み立て |
| `studybot/database.py`・`stats.py` | DBの初期化・保存と集計 |
| その他の `studybot/*.py` | SGの復習・計画、用語集、試験日、朝の通知などのデータ処理 |

新しいコマンドを足すときは、`studybot/features/` の該当するファイルに `@sg_group.command(...)` のように追加します。新しいファイルを作った場合は `studybot/app.py` の `FEATURE_MODULES` にも加えてください。

## データの保存場所

- 学習データ：`data/study.db`
- SG単語帳の学習履歴：`data/sg_glossary_history.db`
- 実行ログ：`studybot.log`
- Discordトークン：`.env`

これらはGitHubへ送信されません。PCを移行する場合、過去の学習履歴を引き継ぐには `data/study.db` と `data/sg_glossary_history.db` を別途バックアップしてください。

## Botの操作

Windows PCでは `manage_studybot.bat` をダブルクリックすると、起動・停止・再起動・状態確認を番号で選べます。既存のタスクスケジューラ `StudyBot` を操作するので、実行前にタスクが登録されている必要があります。

## 更新方法

Gitで保存した場合は、Botを終了してからプロジェクトフォルダで次を実行します。

```powershell
git pull --ff-only
.\setup_studybot.bat
```

その後、`.\start_studybot.bat` で再起動します。セットアップを再実行しても既存の `.env` とDBは維持されます。

## テスト

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## セキュリティ上の注意

- `.env` やDiscord BotトークンをGitへ追加しないでください。
- `data/study.db` と `data/sg_glossary_history.db` には学習履歴が入るため、公開しないでください。
- `studybot.log` を共有するときは、内容を確認してください。
- トークンが漏れた場合はDiscord Developer Portalですぐに再発行してください。
